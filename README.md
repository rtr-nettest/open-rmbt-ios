Open-RMBT iOS App
=================

OpenRMBT is an open source, multi-threaded bandwidth test used in [RTR-Netztest]. This repository contains the sources for the iOS App. For server and Android App sources, see [https://github.com/rtr-nettest].

OpenRMBT is released under the [Apache License, Version 2.0]. The iOS App was developed by [appscape] and financed by the [Austrian Regulatory Authority for Broadcasting and Telecommunications (RTR)](https://www.rtr.at).

Requirements
------------

* **Xcode 16.2 or newer** (developed against Xcode 26). The project file uses `objectVersion = 71`, which older Xcode versions cannot open.
* **iOS 17.0+** deployment target.
* **Ruby 3.1 or newer.** The Ruby that ships with macOS is 2.6 and will *not* work — install a modern one, e.g. `brew install ruby`.
* **CocoaPods via Bundler.** Do not use a globally installed `pod`; the exact version is pinned in `Gemfile.lock`.

Building
--------

```bash
# Use a modern Ruby (skip if yours is already >= 3.1)
eval "$(/opt/homebrew/bin/brew shellenv)"
export PATH="/opt/homebrew/opt/ruby/bin:$PATH"
ruby -v   # must report 3.1 or newer

git clone https://github.com/rtr-nettest/open-rmbt-ios.git
cd open-rmbt-ios

bundle install                        # installs CocoaPods into ./vendor/bundle
bundle exec pod install --repo-update # generates Pods/ and Pods.xcodeproj

# Generate the configuration files once, before the first build (see below)
./Scripts/update_configurations_from_private.sh

open RMBT.xcworkspace                 # the workspace, NOT RMBT.xcodeproj
```

Then build the `RMBT` scheme. A clean clone builds without any further setup — no API keys, credentials or private assets are required.

The `Scripts/update_configurations_from_private.sh` step matters: `Configs/RMBTConfig.swift` is generated by a build phase, but Xcode resolves the compiler's input files *before* running that phase, so on a brand-new clone the **first** build fails with:

```
error: Build input file cannot be found: '.../Configs/RMBTConfig.swift'
```

Running the script once beforehand avoids this. If you hit it anyway, simply build a second time — the file now exists and the build succeeds.

From the command line:

```bash
xcodebuild -workspace RMBT.xcworkspace -scheme RMBT \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro,OS=latest' build
```

### Troubleshooting

* **`Could not find 'bundler' (x.y.z) required by your Gemfile.lock`** — you are on macOS system Ruby 2.6. Install and use Ruby 3.1+ (see above). The message is misleading; installing the suggested bundler version will not help.
* **`No such module 'Alamofire'`, missing `Pods-RMBT.debug.xcconfig`, or `The sandbox is not in sync with the Podfile.lock`** — `pod install` has not been run successfully, or you opened `RMBT.xcodeproj` instead of `RMBT.xcworkspace`.
* **`[Xcodeproj] Unable to find compatibility version string for object version '71'`** — your CocoaPods bundles `xcodeproj` older than 1.28.1. Run `bundle install` to pick up the pinned version; if you are using a global `pod`, switch to `bundle exec pod`.
* **`Build input file cannot be found: '.../Configs/RMBTConfig.swift'`** — expected on the very first build of a fresh clone. Run `./Scripts/update_configurations_from_private.sh`, or just build again.
* **Clone fails with `Permission denied (publickey)`** — you used `git clone --recursive` without access to the private `private/` submodule. Clone without `--recursive`; the public configuration is a complete fallback. An already-cloned worktree is fine as-is.

Configuration
-------------

Build settings, `Info.plist` and app icons come from one of two configuration folders, copied into place by `Scripts/update_configurations_from_private.sh` on **every** build:

* `private/` — RTR's branded configuration, a Git submodule pointing at a private repository. Only accessible to RTR; requires `git submodule update --init`.
* `public/` — the open source configuration, used automatically whenever `private/` is absent or empty.

**Clone without `--recursive`** unless you have access to the private submodule; the public configuration is a complete, working fallback.

Always make configuration changes in `private/` or `public/`, never in the generated destinations:

| Generated file | Tracked in Git? |
| --- | --- |
| `Configs/RMBTConfig.swift` | no (`.gitignore`) |
| `Resources/Images.xcassets/AppIcon.appiconset/` | no (`.gitignore`) |
| `Resources/RMBT-Info.plist` | **yes** |

Because `Resources/RMBT-Info.plist` is tracked *and* regenerated on every build, it shows up as a local modification whenever your configuration source differs from whatever was last committed. The two versions are not equivalent — the private one sets the `RTR-NetTest` display name, the `rmbtat` URL scheme, `NSLocalNetworkUsageDescription` (needed for the DNS QoS test) and `UIBackgroundModes: location` (needed for coverage measurements).

**Do not commit `Resources/RMBT-Info.plist` unless you intend to change it for everyone.** If you build with the public configuration, `git checkout -- Resources/RMBT-Info.plist` before committing; otherwise you will strip RTR's branding and the background-location capability from the repository.
